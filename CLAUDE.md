# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An agent-driven **general video editor** (v3). A human drops in raw footage and a rough idea; an FSM walks them through `INGEST → INSPECT → INTENT → PLAN → COMPOSE → PREVIEW → RENDER → PACKAGE → ITERATE`, producing a packaged video of **any format and any length** — short-form social, multi-short fan-out, segmented long-form with chapters, 24fps cinematic, tutorial, podcast→video — steered by a **video-type preset** system (see the invariants below). (`PLAN` is the merged former `BRIEF` + `STORYBOARD`: one gate that produces the brief and the storyboard together for a single human sign-off.) Rendering is done by [hyperframes](https://github.com/heygen-com/hyperframes) (via a once-per-process resolved binary — no npx); probing/thumbnailing/packaging/assembly by `ffmpeg`/`ffprobe`.

This repo is a *template* you install into a target project. `mcp/` is the engine; `adapters/<cli>/` binds it to a specific agentic CLI (`claude-code` and `opencode` ship today). Both bind the *same* engine in each CLI's idioms — see `adapters/README.md` for the contract mapping. The claude-code orchestrator is a slim SKILL.md spine + per-phase files under `skills/vob/phases/` read on phase entry (OpenCode mirrors them under `.opencode/vob/`). OpenCode specifics: the orchestrator is a `vob` **primary agent** (`.opencode/agents/vob.md`) reached via a thin `/vob` **command**; the three subagents are `mode: subagent` files; MCP registration + permissions live in `opencode.json`; a session write-guard **plugin** blocks direct writes under `~/video-vob-sessions/`. Because OpenCode prefixes MCP tool names with the server key (`vob`), the engine's `vob_*` tools are referenced there as `vob_vob_*`.

## Commands

```bash
npm run mcp                          # start the MCP server (stdio) — node mcp/server.js
node scripts/m5-walker.js [phase]    # end-to-end FSM walker; phase ∈ setup|preview|render|package|all|fanout|general|longform|overlays|gaps|stillsqc|captions|transitions|layout|spans|editorial
./install.sh <target_dir> [adapter]  # copy mcp/ + adapter config + .vob/ into a project (adapter defaults to claude-code)
node scripts/port-adapter-docs.js    # regenerate the OpenCode phase/reference/agent docs from the claude-code sources (run after editing them)
```

In an installed project, the user runs the `/vob` skill inside Claude Code to drive the pipeline. It accepts both the positional form (`/vob <project_id> <source_path>`) and a conversational form where the args are partial, omitted, or carry a freeform "rough idea" (the skill derives the project_id from the source basename and feeds the idea into INTENT) — see the skill's *Argument parsing* section.

- **No test suite, no linter, no typecheck, no CI.** `scripts/m5-walker.js` is the de-facto integration test: it calls `executeTool` (schema validation + envelope — not bare handlers) against a real video (`VOB_WALKER_SOURCE`) and models current conventions (scene clips `./source/<scene_id>-<clip_index>.mp4`, `data-media-start="0"`, clip class, plan-lint-clean storyboard, QC-clean composition); it exercises the plan-lint and composition-QC negative paths too. It requires `ffmpeg` + an installed `hyperframes`. The v3 phases are standalone executable specs: `general` (presets/rulesets/fps), `longform` (segmented render + assembly, REAL renders), `overlays` (typed overlay layer), `gaps` (b-roll shopping list + PLAN→INGEST loop).
- **The MCP server has zero npm dependencies** — pure Node stdlib, CommonJS, Node ≥22. There is no `node_modules`. `package.json` declares no `dependencies`.

## Architecture: two layers

**`mcp/` — the engine (adapter-agnostic).** Owns all durable FSM state, the transition rules, the gate preconditions, the tool registry, and the runners for hyperframes/ffmpeg. This is the single source of truth. Adapters must never duplicate or reimplement logic from here (see `adapters/README.md`).

**`adapters/claude-code/` — the binding.** A `/vob` skill (the *orchestrator*), three subagents, settings, and hooks. The skill drives the human conversation and calls MCP tools; it never invents state.

The contract between the layers is deliberately narrow: **the MCP server enforces structure (required intent keys, confirmation semantics, gate preconditions); the skill owns wording and UX.** The five required intent keys (`target_platform`, `target_duration`, `tone`, `key_moments`, `music_vo` — see `mcp/lib/intent-schema.js`) are a hard contract — do not rename them. v3 adds a third key class: OPTIONAL keys (`video_type`) that are recordable but never required and never gate. Question phrasing, brief structure, etc. are skill-layer concerns.

### State lives outside the repo

All session state is under `~/video-vob-sessions/<project_id>/` (see `mcp/lib/paths.js`), **not** in the working tree. `state.json` is the only authoritative FSM state; markdown/JSON artifacts (`brief.md`, `storyboard.json`, `compose/`, `renders/`, `package/`) are derived. **Never write `state.json`, `manifest.json`, or `brief.md` by hand — only the `vob_*` MCP tools may** (both adapters enforce this with a real guard: a PreToolUse hook on claude-code, a plugin on OpenCode; cross-project reads stay open for `--like`; the ONE write carve-out both guards sanction is `<session>/<project>/work/` — the escape-hatch scratch dir for user-approved bespoke ffmpeg/hyperframes builds; segment-exact, dot-segment steering into `state.json` impossible on both (the claude-code hook rejects `..`/`.` segments outright; the OpenCode plugin `path.resolve`-normalizes before the check), results recorded via `vob_import_deliverable`). All state writes go through `writeFileAtomic` (temp + rename) under a per-session exclusive lock (`acquireSessionLock` / `withSessionLock` in `mcp/lib/storage.js`; lock at `.session.lock`, stale after 5 min; `withSessionLock` is async-aware — it holds the lock until a promise-returning callback settles).

### The FSM is defined in two files that must agree

- **`mcp/lib/session-state.js` → `ALLOWED_TRANSITIONS`**: which edges exist (forward + explicit back-edges). `transitionPhase` is the heart of the engine.
- **`mcp/lib/phase-gates.js` → `GATES`**: one pure function per edge `"FROM->TO"`, returning `{ allowed, blockers }`. Gates check disk artifacts, not just the state summary (the disk is the source of truth — a stale state slot can't fake out a gate).

`transitionPhase` validates the edge against `ALLOWED_TRANSITIONS`, runs the matching gate, and refuses unless `allowed` or an `override_reason` is supplied (overrides are recorded in `state.history` for audit). **Changing or adding an FSM edge means editing both files.** Never skip forward; use the explicit back-edges. Blockers carrying `overridable:false` refuse `override_reason` entirely (see the confirm-then-transition invariant below).

### Tool layer

Every tool is a self-describing frozen module (`mcp/lib/tools/<name>.js`) exporting `{ name, description, inputSchema, handler, ...metadata }`. The metadata block (`role_bundles`, `mutating`, `network_access`, `session_artifacts_written`, etc.) is **required** — `defineTool` in `mcp/lib/tool-registry.js` validates every field at registry-build time and throws on a missing/mistyped field or duplicate name.

Request flow: `transport.js` (stdio) → `dispatch.js::executeTool` → validate args (`tool-validation.js`) → run `handler` → wrap result in an envelope. **Handlers return plain data or throw `ToolError`; they never build envelopes themselves.** `envelope.js` wraps success as `{ ok:true, data, meta }` and failure as `{ ok:false, error:{code,message,details}, meta }`, classifying errors into `ERROR_CODES` (`STATE_CONFLICT`, `INVALID_ARGUMENTS`, `NOT_FOUND`, …). Handler errors classify via ToolError codes only — the vestigial BOB2 classification (SCOPE_BLOCKED/AUTH_MISSING, scope/wave regexes) is gone.

**To add a tool:** create the module with the full metadata block → register it in `mcp/lib/tools/index.js` (`TOOL_MODULES`) → set its `role_bundles` → expose it to the orchestrator in **both** `adapters/claude-code/.claude/skills/vob/SKILL.md` (`allowed-tools`) **and** `adapters/claude-code/.claude/settings.json` (`permissions.allow`). Both lists are maintained by hand and must stay in sync. A boot drift guard (`verifyAdapterToolReferences` in `registry-integrity.js`) cross-checks SKILL.md allowed-tools, settings.json permissions.allow, and the OpenCode frontmatter tool keys against the registry and exits 1 on an unknown name or a leaked subagent write tool.

### Subagents

The orchestrator delegates three phases to subagents with deliberately narrow tool access (read-only upstream + a single write tool each):

- **`inspector`** (`mcp/lib/tools/save-classification.js`, schema in `classification-schema.js`) — classifies INSPECT segments into the A-roll pool / B-roll index / review bucket, records structured visual fields and hook tags. Its only write is `vob_save_classification`.
- **`storyboarder`** (`mcp/lib/tools/save-storyboard.js`, schema in `storyboard-schema.js`) — turns brief + manifest into `storyboard.json`. Its only write is `vob_save_storyboard`.
- **`composer`** (`save-composition.js`, validation in `composition-files.js`) — turns the storyboard into hyperframes HTML/CSS/JS. Its only write is `vob_save_composition`.

Subagents never render, confirm, or transition, and never invoke lint as a tool — the orchestrator owns all of that. (The composer still gets the lint verdict: `save_composition` itself runs the merged lint engine-side after committing and returns it, so the composer self-corrects to a clean save before handoff — see the invariants below.) Spawn prompts are data-only (project_id, paths, intent values, revision notes); all behavioral contract lives in the agent .md files. Composer fix recipes for lint/QC codes live in `skills/vob/references/lint-rules.md`, read when a save verdict or retry carries a code. **Adding a subagent requires registering its `name` in `VALID_ROLE_BUNDLES` (`tool-registry.js`)**: a boot-time integrity check (`registry-integrity.js`, run from `server.js`) cross-checks every `agents/*.md` against that list and **exits 1** if an agent file has no matching bundle. This encodes the "M3 lesson" — a subagent without a role-bundle registration silently fails to be invokable.

## Invariants worth knowing before editing

- **Confirm-then-transition, with resets.** Phases that need human sign-off follow save → confirm → transition. The merged `PLAN` gate requires BOTH `confirm-brief` AND `confirm-storyboard` (presented to the human as one "approve the plan" moment); `confirm-preview` and `confirm-render` gate their phases; COMPOSE→PREVIEW is gated by lint+approval rather than an explicit confirm tool. Re-saving a composition resets `preview.confirmed:false` AND `render.confirmed:false` (lint_status resets to `"unknown"` at commit, then the save-time merged lint immediately stamps the real verdict — `"unknown"` survives only when the lint binary itself failed); re-rendering resets its own confirm; renders stamp `composition_revision_rendered` and the preview→render / render→package gates block on a stale stamp. `inspect_not_acknowledged`, `preview_not_confirmed`, and `render_not_confirmed` are `overridable:false` — `transitionPhase` refuses `override_reason` for them (this was aspirational in v1; it is enforced in v2). All other blockers stay overridable (e.g. the sanctioned ffmpeg-installed-since-INGEST override at RENDER→PACKAGE). A corrupt `inspect.json` at INTENT→PLAN surfaces as an `inspect_summary_unreadable` blocker instead of silently dropping the conditional intent keys.
- **Tool returns are lean by contract.** `transition_phase` returns `{project_id, from, to, override_reason, archived, clips, phase_summary}` (no state echo); `read_state` replaces history/clips/dependencies with digests unless `include:["history","clips","dependencies"]`; `read_state_summary` is the orchestrator's workhorse per-slot digest; `record_intent_answer` returns `{recorded, missing_required_keys}`; lint/save results carry ≤10 findings inline + counts + a report path. On-disk state.json is unchanged and back-compatible (read-time defaults).
- **Platform profiles + intent canonicalization.** `mcp/lib/platform-profiles.js` owns canonical platforms (tiktok/reels/shorts/youtube/landscape/square + a `vertical` fallback + aliases) → dimensions/fps/safe-bands/duration ideals/caption defaults. `record_intent_answer` canonicalizes `target_platform` (`{raw, canonical, profile}`) and `target_duration` (`{raw, seconds, range?, per_deliverable?}` — `parseDurationSpec` parses ranges like `"20–35s"` to `{min_seconds,max_seconds}` with `seconds` = the rounded midpoint, and strip-then-parses trailing per-deliverable qualifiers like `"per short"`/`"each"`, the live-run input that used to canonicalize to `seconds:null`) at record time; downstream consumers (storyboard target block, composer dims, package) never parse free text. `.vob-config/render-profiles.json` overrides shallow-merge into this module.
- **Plan lint + composition QC + render verification.** `save_storyboard` runs a content-quality pass (errors reject the save; warnings ride into the result, state, and storyboard.md for the plan gate); `save_composition` runs a static QC scan (`composition-qc.js`, `vob/*` codes — structural errors reject with `details.qc_findings`; findings fold into the lint report's single findings list; a zero-`<video>` overlay composition downgrades scene-coverage to a `vob/overlay_scene_missing_clip` warning) and then, on an accepted save, the FULL merged lint (same handler as `vob_lint_composition`) — the save result carries the gate verdict (`lint_status` + `lint.findings_summary` + `lint.report_path`) so the composer self-corrects pre-handoff (≤3 saves/invocation; a lint infra failure degrades to `lint_status:"unknown"` + `lint_error`, the save stands). The QC clip-class rule mirrors the installed hyperframes rule EXACTLY (`<video>`/`<audio>`/script/style/template exempt — hyperframes *requires* timed media via `media_missing_data_start`; any of data-start/data-duration/data-track-index triggers; exact `clip` token), and the merged report dedupes hyperframes' location-less copies against equivalent vob findings credit-wise (at most one drop per vob finding); render results carry ffprobe `verification` deltas (`duration_drift_seconds` > 0.5 = silent truncation, plus dims/size). (v3.8: drift now expects the REALIZED speed/layout-baked cut — `realizedScopeDurationSeconds` — not the declared `total_target_duration_seconds`, which legitimately differs; and `verifyRenderedMp4({checkContent:true})` adds ADVISORY black-frame (`signalstatsLuma` sampling) + silent-audio (`measureMaxVolumeDb`) flags on preview + full render.)
- **Multi-short fan-out is first-class (active-short model, schema 1.1).** A storyboard may declare top-level `shorts[]` (one timeline per short: `{short_id, title, sequence, total_target_duration_seconds, scenes[], broll_placements?, notes?}`; requires `schema_version:"1.1"`; top-level `scenes`/`total_target_duration_seconds`/`broll_placements` must then be ABSENT; scene_ids are globally unique — `PLAN_DUPLICATE_SCENE_ID` rejects, both modes). `storyboardTimelines()/allStoryboardScenes()/findTimeline()` in `storyboard-schema.js` are the mode-agnostic accessors every consumer uses. ONE plan gate signs off the whole set (plan lint runs per short, findings tagged `short_id` + `[short_id]` message prefix; key-moment coverage stays document-global; with an intent range, `PLAN_SHORT_DURATION_OUT_OF_RANGE` replaces per-short drift). COMPOSE entry materializes the UNION of all shorts' clips; the singleton COMPOSE→PREVIEW→RENDER machinery then cycles per short: `save_composition{short_id}` (REQUIRED on a fan-out storyboard) stamps `state.composition.short_id`, which scopes QC scene-coverage/master-duration at BOTH call sites (save + `lint_composition`), render timeouts/drift verification, and snapshot defaults to that short (`vob/cross_short_clip_ref` warns on refs into other shorts' clips; unresolved-ref expected lists carry the active short's clips). After `confirm_render` the orchestrator records the short via `vob_import_deliverable {deliverables:[{path,title,short_id}], normalize:true, set_phase:false}` — `short_id` is REQUIRED per entry on a fan-out storyboard and is the record's MERGE IDENTITY (re-import replaces that short's record and removes its superseded file; free-form imports keep filename-stem identity; cross-identity stem collisions suffix `-n`, never clobber); `normalize:true` runs the shared two-pass loudness pass (`mcp/lib/loudnorm.js`, extracted from package-output; target is per-video-type as of v3.8 — `resolveLoudnessTarget(state)`, default −14 LUFS, cinematic −16/wide-LRA, podcast −16); files from the session's `renders/` get `origin:"render"`; every import regenerates `deliverables/manifest.json` (the fan-out package manifest). Then back-edge RENDER→COMPOSE for the next short (archival keeps everything; the deliverable copy is already safe). `vob_package_output` REFUSES (STATE_CONFLICT, before any wipe) on a fan-out project; RENDER→PACKAGE and PACKAGE→ITERATE both block with OVERRIDABLE `shorts_missing_deliverables` (listing missing short_ids) until every short has a record — the backstop for import's direct phase jump. `read_state_summary` carries `storyboard.{short_count,shorts[]}`, `composition.short_id`, `deliverables[]` (lean), and `target_duration_range` so the orchestrator can compute the active short on resume. (v3: `shorts[]` is legal under schema 1.1 OR 1.2; it stays mutually exclusive with `segments[]`.)
- **Video-type presets generalize the format (v3 P1) — data, not branches.** `mcp/lib/video-types.js` is the single resolver: a preset (`social-short`/`long-form`/`cinematic`/`tutorial`/`podcast`/`general` + user presets from `.vob-config/video-types.json`, shallow-merged; unknown names fall back to `general`, never an error) bundles `platform_default`, `editorial.{clean_cut,scene_detect}`, `lint_ruleset` (`retention`/`chaptered`/`montage`/`general`), `overlay_vocabulary`, and `render.segmentation`. `resolveActiveVideoType(state)` is the ONE precedence chain: `VOB_VIDEO_TYPE` env > recorded `video_type` answer (canonicalized at record time, `{raw,canonical,preset?}`; unrecognized stores `canonical:null` and falls through) > derivation from platform+duration (`deriveVideoType`) > `social-short` (byte-for-byte v2.1). Plan lint is ruleset-gated via `activeLintRules(state)`: hook heuristics under `retention` only; clean-speech straddles only when `editorial.clean_cut`; `chaptered` adds `PLAN_CHAPTERS_MISSING`/`PLAN_SECTION_IMBALANCE`. `platform-profiles.js` gained `youtube_long`/`cinematic` (24fps)/`tutorial` profiles (fps is real per-profile data; storyboard `target.fps` → composer `data-fps`, cross-checked by QC `vob/fps_mismatch`). `read_state_summary.video_type` and `vob_doctor` (`report.video_types`, + per-project with `project_id`) surface the resolution. `VOB_VIDEO_TYPES_FILE` overrides the config path.
- **Segmented render + assembly is the length unlock (v3 P2) — fan-out generalized with a join.** Schema 1.2 `segments[]` = narrative acts/chapters (contiguous partition of `scenes[]`, in order; titles become YouTube chapters at PACKAGE); `render_segmentation` `single`(default)/`auto`/`manual` + the preset decide the RENDER chunking (`render-segments.js::deriveRenderPlan` — auto chunks consecutive scenes to the host `<video>` budget respecting narrative boundaries, collapses to single when one chunk fits; `sceneVideoCount` counts PiP overlays). COMPOSE entry stamps `state.render_plan` (single mode deletes stale plan/registry/assembly). The per-short machinery generalizes: `save_composition{segment_id}` (REQUIRED on a segmented plan; mutually exclusive with `short_id`) scopes QC (`vob/cross_segment_clip_ref`, `vob/active_segment_unresolved`), timeouts, drift, and snapshots; `render_full` writes the partial to `<session>/segment_renders/` — deliberately OUTSIDE `renders/` because the per-segment RENDER→COMPOSE back-edge auto-archives `renders/` (the `deliverables/` precedent) — and stamps a REVISION-BOUND registry entry (`state.segment_renders[id]`: storyboard_revision + scene_ids; a storyboard re-save invalidates every partial); `confirm_render` mirrors confirmation into the registry. **`vob_assemble_video`** joins the partials in plan order: lossless concat-demuxer stream copy for all-cut boundaries; `fade` boundaries re-encode as a duration-preserving 0.25s dip-to-black (NOT xfade — overlap would shorten the total and poison drift verification); optional `music_path` bed (looped, pre-gained, sidechain-ducked under program audio, fixed-gain fallback); ffprobe-verifies the join vs the plan total; the assembled final BECOMES `state.render` (confirmed:false, `composition_revision_rendered` = current) so confirm/package work unchanged. RENDER→PACKAGE blocks with OVERRIDABLE `segments_missing_render`/`video_not_assembled`; `package_output` refuses an unassembled segmented project (before any wipe) and emits `chapters[]` + `video_type` + `assembly` lineage (manifest v1.2 + README).
- **Overlays are a typed, planned, QC-BOUND layer (v3 P3).** Schema 1.2 `scene.overlays[]` entries may be objects `{id (attribute-safe, document-globally unique), type (fixed vocabulary in `video-types.js::OVERLAY_TYPES` incl. `pip` — a pip carries a `<video>` and counts against the budget), start/end_seconds (SCENE-relative), track ≥1, content, position{anchor,offset_px}, style, motion{in,out,dwell_min_s}}`; plain strings stay valid everywhere as freeform notes. Plan lint: `PLAN_OVERLAY_OUT_OF_BOUNDS` (error), `PLAN_OVERLAY_DWELL_TOO_SHORT`/`PLAN_OVERLAY_CONFLICT` (bottom-band + full-frame real-estate groups)/`PLAN_OVERLAY_SAFE_AREA`/`PLAN_KINETIC_CAPTION_NO_SPEECH`/`PLAN_VIDEO_BUDGET_EXCEEDED` (per render unit — whole doc / per segment / per short) warnings. Composition QC enforces the binding: every planned typed overlay needs an element stamped `data-vob-overlay-id="<id>"` (`vob/overlay_missing_element` ERROR — same severity as scene coverage); `vob/overlay_track_zero`/`vob/overlay_element_untimed`/`vob/unplanned_overlay_element` warn. Per-type HTML/CSS recipes live in the adapters' `lint-rules.md`.
- **B-roll is planned, and missing coverage is a first-class GAP (v3 P4).** Schema 1.2 `broll_placements[]` gain `render_mode` (`full_frame`/`pip`/`overlay`) + `motion`; a placement may instead declare `{source:"gap", description, desired_duration_seconds, scene_ref, narration_span?, reason?}` — coverage the ingested footage can't supply (ingested-only stays the rule; no stock/AI b-roll). Every storyboard save regenerates `plan/broll_gaps.json` (`collectBrollGaps`, fan-out-aware) and stamps `broll_gap_count` into the storyboard slot/result/summary; plan lint warns `PLAN_BROLL_GAP_UNFILLED` per gap (informational — gaps never block sign-off). Resolution is the sanctioned **PLAN→INGEST back-edge**: re-ingest the extended drop (content-hash caches make old files cheap), re-walk INSPECT→INTENT (answers persist)→PLAN, re-derive; the next save empties the gap file.
- **Subject compositing is a matted b-roll render mode (v3.3) — leverages hyperframes `remove-background`.** Schema 1.2 `broll_placements[].render_mode` gains `"subject"` (`BROLL_RENDER_MODES`/`BACKDROP_KINDS` in `storyboard-schema.js`): a concrete clip-referencing placement (`clip:{scene_id,clip_index}`, NEVER a gap — `subject`-on-gap rejects) matted off its filmed background and composited over a `backdrop` `{kind: design_token|clip_ref|scene_base}` (+ optional `position{anchor,scale}`, `motion{in,out}`). NO synthesized/stock/AI backdrops — a design token (palette key/#hex/CSS gradient), another INGESTED clip, or the scene's own base only; the same ingested-only contract as the b-roll gap rule, kept human-visible by the plan-lint WARNING `PLAN_SUBJECT_BACKDROP_NOT_INGESTED` (a bad kind / unresolved ref WARNS at the gate and the save STANDS — it never hard-rejects). `PLAN_SUBJECT_BUDGET_EXCEEDED` warns per render unit when total subject seconds exceed the host budget (`host-profile.js::subjectBudget`, `VOB_SUBJECT_SECONDS_MAX`; default 60s low-RAM / 600s else; in `CAPACITY_TIERS`). `render_mode` itself stays 1.2-gated, so `subject` needs schema 1.2 (no new version flag — additive like `target.design`). The matte is a **COMPOSE-entry side effect mirroring `clip-materialize.js`**: `matte-materialize.js::materializeSubjectMattes` runs right after `materializeSceneClips` (input = the already-pre-cut clip, so it's trimmed/sped exactly like the spine), writing an alpha `.webm` under `transcoded/mattes/` keyed by a content-hash sidecar (back-edge re-entry is a no-op), symlinked into `compose/source/<scene_id>-<clip_index>.webm` (`source-symlink.js`). It **DEGRADES, never throws**: a missing/uncached model, a disabled host (`VOB_REMOVE_BG_DISABLE`), an over-budget set, or a failed inference records the matte `skipped`/`unavailable`/`failed` and COMPOSE STILL proceeds (a mid-pipeline matte failure must not strand COMPOSE) — the composer falls back to a rectangular `pip`; subject mode is **ADVISORY at QC** (deliberately NO `data-vob-overlay-id`-style hard binding, unlike typed overlays). Every `remove-background` call flows through the ONE hyperframes runner (`hyperframes-runner.js`: `buildRemoveBackgroundArgv`/`runRemoveBackground` — duration-aware timeout, `retryTimedOut:false`; `checkRemoveBackgroundAvailable` parses `--info --json` for the INGEST `state.dependencies.remove_background` + `vob_doctor` preflight, warn-only, never flips `ok:false`; `VOB_REMOVE_BG_DEVICE` coreml-on-darwin/cpu). Two composer realizations (recipes in `lint-rules.md`): (a) DEFAULT — the matte as an alpha `<video>` over an HTML/CSS `target.design` backdrop, subject AUDIO from the sibling `.mp4` (the matte is visual-only); (b) low-RAM FALLBACK — ffmpeg `overlay-compositor.js::compositeOverlayOverBase` over a `buildBackdropArgv`/`generateBackdrop` design-token backdrop (or a clip base), `audio:` = the subject clip, NOT the muted backdrop. `read_state_summary.subject_mattes{count,matted,cached,skipped,over_budget,backend_available}` + a `subject_mattes_materialized` history event. Walker: `node scripts/m5-walker.js subject` (schema/lint/wiring model-free; the real matte is opt-in via `VOB_WALKER_MATTE=1`).
- **Scene transitions are a typed, planned, ruleset-gated intra-composition layer (v3.3) — CSS via hyperframes' native css adapter, NO GSAP.** `scene.transition_in` widens from `cut`/`fade` to the full typed vocabulary (`video-types.js::TRANSITION_TYPES` + per-preset `transition_vocabulary`, the CSS-family subset; `SEAM_TRANSITION_TYPES`=`cut`/`dip`/`fade`; `SHADER_TRANSITIONS` recognized but gated). - **Clean-cut: filler/dead-air removal for the A-roll.** `clean-cut.js::computeCleanSpans(words, silences, durationSeconds)` turns a word-level transcript + an ffmpeg `silencedetect` map into filler/dead-air-free **keep-spans**.

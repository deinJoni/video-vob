# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

An agent-driven video pipeline. A human drops in raw footage and a rough idea; an FSM walks them through `INGEST → INSPECT → INTENT → PLAN → COMPOSE → PREVIEW → RENDER → PACKAGE → ITERATE`, producing a packaged short-form video. (`PLAN` is the merged former `BRIEF` + `STORYBOARD`: one gate that produces the brief and the storyboard together for a single human sign-off.) Rendering is done by [hyperframes](https://github.com/heygen-com/hyperframes) (via a once-per-process resolved binary — no npx); probing/thumbnailing/packaging by `ffmpeg`/`ffprobe`.

This repo is a *template* you install into a target project. `mcp/` is the engine; `adapters/<cli>/` binds it to a specific agentic CLI (`claude-code` and `opencode` ship today). Both bind the *same* engine in each CLI's idioms — see `adapters/README.md` for the contract mapping. The claude-code orchestrator is a slim SKILL.md spine + per-phase files under `skills/vob/phases/` read on phase entry (OpenCode mirrors them under `.opencode/vob/`). OpenCode specifics: the orchestrator is a `vob` **primary agent** (`.opencode/agents/vob.md`) reached via a thin `/vob` **command**; the three subagents are `mode: subagent` files; MCP registration + permissions live in `opencode.json`; a session write-guard **plugin** blocks direct writes under `~/video-vob-sessions/`. Because OpenCode prefixes MCP tool names with the server key (`vob`), the engine's `vob_*` tools are referenced there as `vob_vob_*`.

## Commands

```bash
npm run mcp                          # start the MCP server (stdio) — node mcp/server.js
node scripts/m5-walker.js [phase]    # end-to-end FSM walker; phase ∈ setup|preview|render|package|all|fanout
./install.sh <target_dir> [adapter]  # copy mcp/ + adapter config + .vob/ into a project (adapter defaults to claude-code)
```

In an installed project, the user runs the `/vob` skill inside Claude Code to drive the pipeline. It accepts both the positional form (`/vob <project_id> <source_path>`) and a conversational form where the args are partial, omitted, or carry a freeform "rough idea" (the skill derives the project_id from the source basename and feeds the idea into INTENT) — see the skill's *Argument parsing* section.

- **No test suite, no linter, no typecheck, no CI.** `scripts/m5-walker.js` is the de-facto integration test: it calls `executeTool` (schema validation + envelope — not bare handlers) against a real video (`VOB_WALKER_SOURCE`) and models current conventions (scene clips `./source/<scene_id>-<clip_index>.mp4`, `data-media-start="0"`, clip class, plan-lint-clean storyboard, QC-clean composition); it exercises the plan-lint and composition-QC negative paths too. It requires `ffmpeg` + an installed `hyperframes`.
- **The MCP server has zero npm dependencies** — pure Node stdlib, CommonJS, Node ≥22. There is no `node_modules`. `package.json` declares no `dependencies`.

## Architecture: two layers

**`mcp/` — the engine (adapter-agnostic).** Owns all durable FSM state, the transition rules, the gate preconditions, the tool registry, and the runners for hyperframes/ffmpeg. This is the single source of truth. Adapters must never duplicate or reimplement logic from here (see `adapters/README.md`).

**`adapters/claude-code/` — the binding.** A `/vob` skill (the *orchestrator*), three subagents, settings, and hooks. The skill drives the human conversation and calls MCP tools; it never invents state.

The contract between the layers is deliberately narrow: **the MCP server enforces structure (required intent keys, confirmation semantics, gate preconditions); the skill owns wording and UX.** The five required intent keys (`target_platform`, `target_duration`, `tone`, `key_moments`, `music_vo` — see `mcp/lib/intent-schema.js`) are a hard contract — do not rename them. Question phrasing, brief structure, etc. are skill-layer concerns.

### State lives outside the repo

All session state is under `~/video-vob-sessions/<project_id>/` (see `mcp/lib/paths.js`), **not** in the working tree. `state.json` is the only authoritative FSM state; markdown/JSON artifacts (`brief.md`, `storyboard.json`, `compose/`, `renders/`, `package/`) are derived. **Never write `state.json`, `manifest.json`, or `brief.md` by hand — only the `vob_*` MCP tools may** (both adapters enforce this with a real guard: a PreToolUse hook on claude-code, a plugin on OpenCode; cross-project reads stay open for `--like`; the ONE write carve-out both guards sanction is `<session>/<project>/work/` — the escape-hatch scratch dir for user-approved bespoke ffmpeg/hyperframes builds; segment-exact, dot-segment steering into `state.json` impossible on both (the claude-code hook rejects `..`/`.` segments outright; the OpenCode plugin `path.resolve`-normalizes before the check), results recorded via `vob_import_deliverable`). All state writes go through `writeFileAtomic` (temp + rename) under a per-session exclusive lock (`acquireSessionLock` / `withSessionLock` in `mcp/lib/storage.js`; lock at `.session.lock`, stale after 5 min; `withSessionLock` is async-aware — it holds the lock until a promise-returning callback settles).

### The FSM is defined in two files that must agree

- **`mcp/lib/session-state.js` → `ALLOWED_TRANSITIONS`**: which edges exist (forward + explicit back-edges). `transitionPhase` is the heart of the engine.
- **`mcp/lib/phase-gates.js` → `GATES`**: one pure function per edge `"FROM->TO"`, returning `{ allowed, blockers }`. Gates check disk artifacts, not just the state summary (the disk is the source of truth — a stale state slot can't fake out a gate).

`transitionPhase` validates the edge against `ALLOWED_TRANSITIONS`, runs the matching gate, and refuses unless `allowed` or an `override_reason` is supplied (overrides are recorded in `state.history` for audit). **Changing or adding an FSM edge means editing both files.** Never skip forward; use the explicit back-edges. Blockers carrying `overridable:false` refuse `override_reason` entirely (see the confirm-then-transition invariant below).

### Tool layer

Every tool is a self-describing frozen module (`mcp/lib/tools/<name>.js`) exporting `{ name, description, inputSchema, handler, ...metadata }`. The metadata block (`role_bundles`, `mutating`, `network_access`, `session_artifacts_written`, etc.) is **required** — `defineTool` in `mcp/lib/tool-registry.js` validates every field at registry-build time and throws on a missing/mistyped field or duplicate name.

Request flow: `transport.js` (stdio) → `dispatch.js::executeTool` → validate args (`tool-validation.js`) → run `handler` → wrap result in an envelope. **Handlers return plain data or throw `ToolError`; they never build envelopes themselves.** `envelope.js` wraps success as `{ ok:true, data, meta }` and failure as `{ ok:false, error:{code,message,details}, meta }`, classifying errors into `ERROR_CODES` (`STATE_CONFLICT`, `INVALID_ARGUMENTS`, `NOT_FOUND`, …). Handler errors classify via ToolError codes only — the vestigial BOB2 classification (SCOPE_BLOCKED/AUTH_MISSING, scope/wave regexes) is gone.

**To add a tool:** create the module with the full metadata block → register it in `mcp/lib/tools/index.js` (`TOOL_MODULES`) → set its `role_bundles` → expose it to the orchestrator in **both** `adapters/claude-code/.claude/skills/vob/SKILL.md` (`allowed-tools`) **and** `adapters/claude-code/.claude/settings.json` (`permissions.allow`). Both lists are maintained by hand and must stay in sync. A boot drift guard (`verifyAdapterToolReferences` in `registry-integrity.js`) cross-checks SKILL.md allowed-tools, settings.json permissions.allow, and the OpenCode frontmatter tool keys against the registry and exits 1 on an unknown name or a leaked subagent write tool.

### Subagents

The orchestrator delegates three phases to subagents with deliberately narrow tool access (read-only upstream + a single write tool each):

- **`inspector`** (`mcp/lib/tools/save-classification.js`, schema in `classification-schema.js`) — classifies INSPECT segments into the A-roll pool / B-roll index / review bucket, records structured visual fields and hook tags. Its only write is `vob_save_classification`.
- **`storyboarder`** (`mcp/lib/tools/save-storyboard.js`, schema in `storyboard-schema.js`) — turns brief + manifest into `storyboard.json`. Its only write is `vob_save_storyboard`.
- **`composer`** (`save-composition.js`, validation in `composition-files.js`) — turns the storyboard into hyperframes HTML/CSS/JS. Its only write is `vob_save_composition`.

Subagents never render, confirm, or transition, and never invoke lint as a tool — the orchestrator owns all of that. (The composer still gets the lint verdict: `save_composition` itself runs the merged lint engine-side after committing and returns it, so the composer self-corrects to a clean save before handoff — see the invariants below.) Spawn prompts are data-only (project_id, paths, intent values, revision notes); all behavioral contract lives in the agent .md files. Composer fix recipes for lint/QC codes live in `skills/vob/references/lint-rules.md`, read when a save verdict or retry carries a code. **Adding a subagent requires registering its `name` in `VALID_ROLE_BUNDLES` (`tool-registry.js`)**: a boot-time integrity check (`registry-integrity.js`, run from `server.js`) cross-checks every `agents/*.md` against that list and **exits 1** if an agent file has no matching bundle. This encodes the "M3 lesson" — a subagent without a role-bundle registration silently fails to be invokable.

## Invariants worth knowing before editing

- **Confirm-then-transition, with resets.** Phases that need human sign-off follow save → confirm → transition. The merged `PLAN` gate requires BOTH `confirm-brief` AND `confirm-storyboard` (presented to the human as one "approve the plan" moment); `confirm-preview` and `confirm-render` gate their phases; COMPOSE→PREVIEW is gated by lint+approval rather than an explicit confirm tool. Re-saving a composition resets `preview.confirmed:false` AND `render.confirmed:false` (lint_status resets to `"unknown"` at commit, then the save-time merged lint immediately stamps the real verdict — `"unknown"` survives only when the lint binary itself failed); re-rendering resets its own confirm; renders stamp `composition_revision_rendered` and the preview→render / render→package gates block on a stale stamp. `inspect_not_acknowledged`, `preview_not_confirmed`, and `render_not_confirmed` are `overridable:false` — `transitionPhase` refuses `override_reason` for them (this was aspirational in v1; it is enforced in v2). All other blockers stay overridable (e.g. the sanctioned ffmpeg-installed-since-INGEST override at RENDER→PACKAGE). A corrupt `inspect.json` at INTENT→PLAN surfaces as an `inspect_summary_unreadable` blocker instead of silently dropping the conditional intent keys.
- **Tool returns are lean by contract.** `transition_phase` returns `{project_id, from, to, override_reason, archived, clips, phase_summary}` (no state echo); `read_state` replaces history/clips/dependencies with digests unless `include:["history","clips","dependencies"]`; `read_state_summary` is the orchestrator's workhorse per-slot digest; `record_intent_answer` returns `{recorded, missing_required_keys}`; lint/save results carry ≤10 findings inline + counts + a report path. On-disk state.json is unchanged and back-compatible (read-time defaults).
- **Platform profiles + intent canonicalization.** `mcp/lib/platform-profiles.js` owns canonical platforms (tiktok/reels/shorts/youtube/landscape/square + a `vertical` fallback + aliases) → dimensions/fps/safe-bands/duration ideals/caption defaults. `record_intent_answer` canonicalizes `target_platform` (`{raw, canonical, profile}`) and `target_duration` (`{raw, seconds, range?, per_deliverable?}` — `parseDurationSpec` parses ranges like `"20–35s"` to `{min_seconds,max_seconds}` with `seconds` = the rounded midpoint, and strip-then-parses trailing per-deliverable qualifiers like `"per short"`/`"each"`, the live-run input that used to canonicalize to `seconds:null`) at record time; downstream consumers (storyboard target block, composer dims, package) never parse free text. `.vob-config/render-profiles.json` overrides shallow-merge into this module.
- **Plan lint + composition QC + render verification.** `save_storyboard` runs a content-quality pass (errors reject the save; warnings ride into the result, state, and storyboard.md for the plan gate); `save_composition` runs a static QC scan (`composition-qc.js`, `vob/*` codes — structural errors reject with `details.qc_findings`; findings fold into the lint report's single findings list; a zero-`<video>` overlay composition downgrades scene-coverage to a `vob/overlay_scene_missing_clip` warning) and then, on an accepted save, the FULL merged lint (same handler as `vob_lint_composition`) — the save result carries the gate verdict (`lint_status` + `lint.findings_summary` + `lint.report_path`) so the composer self-corrects pre-handoff (≤3 saves/invocation; a lint infra failure degrades to `lint_status:"unknown"` + `lint_error`, the save stands). The QC clip-class rule mirrors the installed hyperframes rule EXACTLY (`<video>`/`<audio>`/script/style/template exempt — hyperframes *requires* timed media via `media_missing_data_start`; any of data-start/data-duration/data-track-index triggers; exact `clip` token), and the merged report dedupes hyperframes' location-less copies against equivalent vob findings credit-wise (at most one drop per vob finding); render results carry ffprobe `verification` deltas (`duration_drift_seconds` > 0.5 = silent truncation, plus dims/size).
- **Multi-short fan-out is first-class (active-short model, schema 1.1).** A storyboard may declare top-level `shorts[]` (one timeline per short: `{short_id, title, sequence, total_target_duration_seconds, scenes[], broll_placements?, notes?}`; requires `schema_version:"1.1"`; top-level `scenes`/`total_target_duration_seconds`/`broll_placements` must then be ABSENT; scene_ids are globally unique — `PLAN_DUPLICATE_SCENE_ID` rejects, both modes). `storyboardTimelines()/allStoryboardScenes()/findTimeline()` in `storyboard-schema.js` are the mode-agnostic accessors every consumer uses. ONE plan gate signs off the whole set (plan lint runs per short, findings tagged `short_id` + `[short_id]` message prefix; key-moment coverage stays document-global; with an intent range, `PLAN_SHORT_DURATION_OUT_OF_RANGE` replaces per-short drift). COMPOSE entry materializes the UNION of all shorts' clips; the singleton COMPOSE→PREVIEW→RENDER machinery then cycles per short: `save_composition{short_id}` (REQUIRED on a fan-out storyboard) stamps `state.composition.short_id`, which scopes QC scene-coverage/master-duration at BOTH call sites (save + `lint_composition`), render timeouts/drift verification, and snapshot defaults to that short (`vob/cross_short_clip_ref` warns on refs into other shorts' clips; unresolved-ref expected lists carry the active short's clips). After `confirm_render` the orchestrator records the short via `vob_import_deliverable {deliverables:[{path,title,short_id}], normalize:true, set_phase:false}` — `short_id` is REQUIRED per entry on a fan-out storyboard and is the record's MERGE IDENTITY (re-import replaces that short's record and removes its superseded file; free-form imports keep filename-stem identity; cross-identity stem collisions suffix `-n`, never clobber); `normalize:true` runs the shared two-pass −14 LUFS pass (`mcp/lib/loudnorm.js`, extracted from package-output); files from the session's `renders/` get `origin:"render"`; every import regenerates `deliverables/manifest.json` (the fan-out package manifest). Then back-edge RENDER→COMPOSE for the next short (archival keeps everything; the deliverable copy is already safe). `vob_package_output` REFUSES (STATE_CONFLICT, before any wipe) on a fan-out project; RENDER→PACKAGE and PACKAGE→ITERATE both block with OVERRIDABLE `shorts_missing_deliverables` (listing missing short_ids) until every short has a record — the backstop for import's direct phase jump. `read_state_summary` carries `storyboard.{short_count,shorts[]}`, `composition.short_id`, `deliverables[]` (lean), and `target_duration_range` so the orchestrator can compute the active short on resume.
- **COMPOSE entry has a heavy side effect.** `transitionPhase(... to_phase:"COMPOSE")` is `async`/blocking: before committing state it pre-cuts every storyboard `source_clips[i]` into its own H.264 clip at `transcoded/clips/<scene_id>-<clip_index>.mp4` via ffmpeg (`clip-materialize.js`; cached by content-hash sidecar, so back-edge re-entry is a no-op). Every `vob_save_composition` then wipes `compose/` and recreates `compose/source/` symlinks (`source-symlink.js`). Compositions reference scene clips as `./source/<scene_id>-<clip_index>.mp4` with `data-media-start="0"` — never absolute paths, never seeking into the original source.
- **Font kit ships with the engine (23 families, vendored woff2).** `mcp/assets/fonts/` holds a vendored OFL/Apache `.woff2` kit + `mcp/assets/fonts.css` with the `@font-face` rules; **`scripts/build-fonts.js` is the source of truth** — it fetches every family from @fontsource and regenerates `fonts.css` + `fonts/LICENSES.md` from one manifest (re-run `node scripts/build-fonts.js` to refresh to latest; `--css-only` to regenerate CSS without fetching). The set is a SUPERSET of hyperframes' own embedded families (Inter/Montserrat/Poppins/Outfit/Open Sans/Lato/Roboto/Oswald/Archivo Black/League Gothic/EB Garamond/JetBrains Mono/IBM Plex Mono/Source Code Pro/Space Mono/Noto Sans JP/Playfair Display/Nunito) **plus** Anton + Bebas Neue and the house-style faces Hanken Grotesk + **Noto Serif SC / Noto Sans SC** (Simplified Chinese 中文) — so a bilingual/CJK brief is renderable on-rails, not just aspirational. Every `save_composition` symlinks `fonts/` and copies `fonts.css` into `compose/` like `source/`. The composer loads `./fonts.css` and uses kit families by name. **There is no engine-side font allowlist** — the only font constraint is hyperframes' own lint rule `google_fonts_import` (fires on a `fonts.googleapis.com` link/`@import`), which self-hosted `@font-face` never trips; extending the kit = add files + `@font-face`, nothing in `mcp/lib/` to touch. CJK woff2 are ~1–1.5 MB each but lazy-load only when CJK text actually renders (scope a CJK family to the CJK element, never a global fallback). Attributions in NOTICE + `mcp/assets/fonts/LICENSES.md`.
- **Back-edges auto-archive.** Any back-edge out of `RENDER`/`PACKAGE`/`ITERATE` into `COMPOSE`/`PLAN` moves the current `renders/` + `package/` into `archive/v<N>/` before the transition commits (`archival.js`) and bumps the iteration version. The user never loses a prior cut.
- **Lint gates COMPOSE → PREVIEW.** Errors block; warnings are accept-or-fix at the user's discretion. The verdict exists the moment the composer returns (save-time lint); the orchestrator calls `vob_lint_composition` only as the `unknown`-status fallback / disk-truth re-check, and auto-retries the composer on errors (up to 3 re-spawns; the composer also self-corrects up to 3 saves per spawn) before surfacing them.
- **hyperframes/ffmpeg failures surface with install hints.** Runners (`hyperframes-runner.js`, `ffmpeg-runner.js`, `spawn-with-shutdown.js`) classify missing binaries and return actionable errors rather than crashing. Render tools are long-blocking — timeouts scale with storyboard duration, floored at the v1 caps (preview ≥15 min, full ≥30 min; `VOB_RENDER_TIMEOUT_MS`/`VOB_FULL_RENDER_TIMEOUT_MS` override) — and both tee stderr to a log file for `tail -f`.
- **One hyperframes runner — resolved once, no npx, no auto-update.** Every hyperframes call (render/snapshot/lint/transcribe + the `--version` preflight) flows through ONE chokepoint in `hyperframes-runner.js`. `resolveHyperframesCmd()` resolves the installed `hyperframes` **once per process** and runs it under the MCP server's own Node (`node <…>/dist/cli.js`) — **not** `npx --yes hyperframes`, which re-resolved the package on every call (a transient ESM `Cannot find package` race under memory pressure), floated the version, and let the engine **auto-upgrade mid-pipeline** (observed 0.6.64→0.6.69 in a single session, after which BeginFrame capture began timing out). Resolution order: `VOB_HYPERFRAMES_BIN` (explicit `dist/cli.js`) → `hyperframes` on PATH (realpath'd) → `npm root -g` → `npx --yes` fallback. `hyperframesChildEnv()` is the single env policy and pins the engine (`HYPERFRAMES_NO_UPDATE_CHECK`/`HYPERFRAMES_NO_AUTO_INSTALL=1`) and raises Chrome's CDP/readiness timeouts (`PRODUCER_PUPPETEER_PROTOCOL_TIMEOUT_MS=300000`, `PRODUCER_{PLAYER,RENDER}_READY_TIMEOUT_MS=120000` — the 30s/45s defaults cut off the first multi-video frame seek on a low-RAM Mac, failing an otherwise-progressing render). Every default is overridable by exporting the underlying var.
- **Transient hyperframes failures are retried; deterministic ones are not.** `runHyperframesWithRetry()` wraps the spawn and re-runs (bounded, short backoff) on infra/transient errors — `Target closed`, `Protocol error`, `Runtime.callFunctionOn timed out`, browser-launch flakes, the ESM `Cannot find package` race — the exact failures that "work on a re-run" and made wrapped runs flakier than direct ones (the wrapper had **zero** retry; a human just re-ran). It NEVER retries deterministic aborts (`Aborting render`, `--strict` lint, bad args) and NEVER retries a render that **timed out** mid-capture (a 15–30 min job isn't blindly re-run). Budgets: render-full ≤2 attempts, preview/snapshot ≤3, lint retries only an ESM launch flake (a found-errors report is not a transient).
- **Chrome GL backend defaults to software on macOS — now a perf choice, not a hang workaround.** `PRODUCER_BROWSER_GPU_MODE` selects the backend; on `darwin` `resolveBrowserGpuMode()` defaults to `software` (SwiftShader). In current hyperframes (≥0.6.69) `auto` self-falls-back to software (2s BeginFrame race + flag-strip relaunch), so the old Metal/BeginFrame *hang* is moot; software stays the darwin default because the hardware/Metal capture path is the *slow* one that drives the worker clamp on an 8 GB Mac. Set centrally in the runner so it covers `render` **and** `snapshot` (`snapshot` has no `--no-browser-gpu` flag). Override with **`VOB_BROWSER_GPU`** (`off`/`software` force software anywhere, `on`/`hardware` re-enable host GPU, `auto` defers to the probe); **`VOB_FORCE_SCREENSHOT`** forces the screenshot capture path `snapshot` uses (an escape hatch if BeginFrame capture stalls). (`resolveBrowserGpuMode` / `hyperframesChildEnv` in `hyperframes-runner.js`.)
- **Clean-cut: filler/dead-air removal for the A-roll.** `clean-cut.js::computeCleanSpans(words, silences, durationSeconds)` turns a word-level transcript + an ffmpeg `silencedetect` map into filler/dead-air-free **keep-spans**. It trusts the silence map for cut *locations* (Whisper word timings are unreliable across pauses — it timestamps a single "word" across a 2.5s gap) but gates each silence by **word density**: a silence is cut only if ≤1 transcribed word overlaps it (dead air = one loose word bridging a pause; quiet speech is densely worded → kept). It also drops a filler lexicon and detects/removes flubbed retakes. INSPECT runs it (`-40dB` silence pass) and writes `inspect/clean_speech.json {keep_spans, removed, stats}`; `state.inspect.clean_speech_path` is passed to the storyboarder, which snaps `a_roll` cuts to keep-span boundaries (plan lint warns when a clip straddles a removed span). Keep the `<video>`-element count within the host budget — a render with ~14 video elements overwhelms low-RAM headless Chrome (composition QC warns over the budget, errors over the hard cap; defaults 6/8, host-tunable via `.vob-config/host.json` — see the host-profile invariant below). `buildTimeline()` maps source→compressed time so captions/B-roll re-time. (`mcp/lib/clean-cut.js`.)
- **Per-machine capacity tuning lives in `.vob-config/host.json` — one resolver, no source edits.** `mcp/lib/host-profile.js` is the single authority for the host-dependent performance constraints: render workers, heavy-encode concurrency, render quality, the GPU knob, and the composition-QC `<video>` warn-budget / hard-cap (the last two were hardcoded 6/8 before — now tunable). Resolution precedence per setting is **explicit `VOB_*` env var > `host.json` per-key field > `host.json` `capacity` tier (`low`/`medium`/`high`) > RAM-derived default**, so an install with no `host.json` behaves byte-for-byte as before (the historical RAM tiers now live in `host-profile.js`). `host.json` sits in the install root's `.vob-config/` next to `render-profiles.json`, is read once per process, and absent/malformed → defaults silently. The consumers (`concurrency.js`, `hyperframes-runner.js::{renderWorkerArgs,defaultRenderQuality,resolveBrowserGpuMode}`, `composition-qc.js` video caps) all delegate here; `vob_doctor` reports each effective value **and its source** under `report.tuning`. `browser_gpu` is deliberately NOT in the capacity tiers (GPU availability is orthogonal to RAM). New env knobs `VOB_VIDEO_BUDGET` / `VOB_VIDEO_HARD_CAP` join the existing `VOB_RENDER_WORKERS` / `VOB_ENCODE_CONCURRENCY` / `VOB_RENDER_QUALITY` / `VOB_BROWSER_GPU`. Env knobs are the per-process path (set them in the adapter MCP launch config's `env` block); `host.json` is the committed-per-machine path. Template: `.vob-config/host.example.json`.
- **Render worker count — default 1 on low-RAM, and `auto` does NOT skip calibration.** hyperframes auto-calibrates worker count by timing sample frames (a ~30s/frame BeginFrame probe) whenever `--workers` is unset **or set to the literal `auto`** (the CLI treats `auto` as undefined); on a low-RAM/software-GPU Mac that probe times out, falls back to a screenshot probe that also fails, then clamps to 1 worker anyway (older hyperframes aborted the render outright). A **positive integer** `--workers` SKIPS calibration. `renderWorkerArgs()` therefore defaults to `--workers 1` on hosts with <10 GB total RAM (and `[]` — defer to hyperframes — on roomier hosts). Override with **`VOB_RENDER_WORKERS`**: a positive int forces that count and skips calibration; `auto` defers to hyperframes (re-enabling calibration). NB: only a positive integer skips calibration — `auto` does not. (`renderWorkerArgs` in `hyperframes-runner.js`.)

- **ASR is a pluggable backend — transcription survives a missing whisper-cpp.** INSPECT no longer calls `hyperframes transcribe` directly. `mcp/lib/asr-backend.js` detects and dispatches to the first working engine — `faster-whisper` (Python) → `openai-whisper` (Python) → `hyperframes` (its internal whisper-cpp) — and on a runtime failure FALLS THROUGH to the next. Every backend writes the SAME canonical `[{text,start,end}]` transcript the rest of the pipeline consumes (the Python drivers live in `mcp/lib/asr/`). Without this, a host lacking whisper-cpp silently reported "no speech" on clear narration, making burned captions inexpressible through the whole FSM. Knobs: `VOB_ASR_BACKEND` (`auto`|`faster-whisper`|`openai-whisper`|`hyperframes`|`none`), `VOB_ASR_MODEL` (default `small.en`), `VOB_ASR_LANGUAGE`, `VOB_PYTHON`, `VOB_ASR_DEVICE`/`VOB_ASR_COMPUTE_TYPE` (ctranslate2), `VOB_ASR_TIMEOUT_MS`. The recommended install on a bare host is `pip install faster-whisper`.
- **`vob_doctor` is the up-front preflight — run it first.** Checks ffmpeg, ffprobe, hyperframes, and (critically) the ASR backend, plus host RAM and the derived render-worker / heavy-encode-concurrency ceilings, and lists advisories for the known gotchas (DJI rotation, `<video>` render fragility, Docker-banned). `ok:false` only for missing ffmpeg/ffprobe; a missing ASR engine is a WARNING. INGEST also runs the ASR/ffmpeg/hyperframes preflight into `state.dependencies` so a dead transcription path surfaces before INSPECT burns minutes.
- **INSPECT timeouts scale with source duration; scene detection is skippable.** The fixed 8-min scene-detect / 10-min transcribe caps guaranteed a timeout on 31–44-min HEVC. `durationAwareTimeout()` (`inspect.js`) now floors the per-pass timeout at the short-clip baseline and scales it up by source duration (overridable per pass: `VOB_SCENE_DETECT_TIMEOUT_MS`, `VOB_SILENCE_DETECT_TIMEOUT_MS`, `VOB_AUDIO_EXTRACT_TIMEOUT_MS`, `VOB_ASR_TIMEOUT_MS`). `vob_inspect_source { skip_scene_detection:true }` skips the slowest whole-stream decode (recommended for long single-shot sources). NB: a skip-scene run NEVER writes the content-hash detection cache, so it can't poison a later full run with `scene_cuts:[]`.
- **INSPECT v2: cheap agent-facing images, richer signal.** Grounding images are downscaled at extraction (thumbs `scale=480:-2`, segment keyframes `scale=512:-2`); INSPECT also emits per-file contact strips + a JSON legend (`inspect/strips/legend.json`), per-file transcripts (`inspect/transcripts/file_<i>.json`), audio features (per-file LUFS via ebur128, per-segment `energy_rms_db`/`speech_rate_wpm`) in segments.json, and `inspect/digest.md` with ranked `hook_candidates[]` — agents read strips + the digest instead of N full-res singles. `snapshot_keyframes` stills stay full-res (human-facing, and the COMPOSE-phase self-QC basis — it is callable right after a save, no lint/preview required). Thumbnails are **seek-based and non-fatal**: one input-side `-ss` single-frame extract per grid slot (never a whole-stream `fps=1/N` decode — that's what timed out on 18-min/35Mbps HEVC), grid hard-capped at 400/file, failed slots filled with nearest-neighbor stand-in copies so `frame_K = second (K−1)×interval` stays exact (the storyboarder's cut-point math depends on it); thumb/contact-sheet failures degrade to `warnings[]` in the result/state/digest instead of aborting INSPECT. Knobs: `VOB_THUMB_TIMEOUT_MS` (whole-pass soft deadline — skips remaining seeks), `VOB_THUMB_SEEK_TIMEOUT_MS` (per-seek, default 60s). Audio-only manifest files are skipped by the thumb pass (no frames).
- **Overlay-over-base is a first-class composite, and `vob_import_deliverable` is the deliverables recorder (on-rails fan-out AND escape hatch).** When hyperframes `<video>` continuous capture is too fragile, render graphics as a TRANSPARENT overlay (no `<video>`), cut the base with ffmpeg, and composite via `mcp/lib/overlay-compositor.js` (`overlay=format=auto` + base-audio mux). `vob_import_deliverable` records finished deliverables into `state.deliverables[]` + a SESSION-LEVEL `deliverables/` dir (deliberately NOT under `package/`, so the single-timeline `vob_package_output` — which wipes `package/` — can't delete them), optionally compositing first and optionally loudness-normalizing (`normalize:true`, shared `mcp/lib/loudnorm.js` pass); it advances phase to PACKAGE (`set_phase:false` to stay put mid-fan-out) and writes an `external_deliverables_imported` audit entry. It does NOT touch the composition/render/preview slots — the point is that `state.json` never lies about finished work, whether it came off the rails (fan-out records, `origin:"render"`) or from the sanctioned `<session>/work/` scratch dir. For an import-only project, PACKAGE is terminal: the `packageToIterate` gate and `vob_finalize_iteration` both accept external deliverables (via `hasExternalDeliverables`) in lieu of a single-timeline package, so it can reach ITERATE instead of dead-ending. Heavy-encode concurrency (`mcp/lib/concurrency.js`) is RAM-derived and capped (`VOB_ENCODE_CONCURRENCY`) to avoid the ≥5-concurrent-encode OOM SIGKILL.
- **DJI bogus-rotation knob.** ffprobe now surfaces display `rotation` per file (manifest + INGEST `rotation_warning`); `VOB_DISABLE_AUTOROTATE=1` adds `-noautorotate` to ffmpeg decodes (`inputAutorotateArgs` in `ffmpeg-runner.js`: clip pre-cut, overlay composite, and INSPECT thumbnail/keyframe extraction) for footage whose rotation tag is bogus. OFF by default — it would mis-orient legitimately rotated phone footage. It is SESSION-GLOBAL (one env var, all files): a single session can't mix a bogus-rotation DJI clip and a legitimately-rotated phone clip and correct only one — `has_rotation` can't distinguish bogus from intended, so per-file autorotation isn't offered.

- **Style inheritance via `--like` — lineage, not a new store.** `vob_init_project` takes an optional `derived_from` (a prior project_id). It validates the source's `state.json` exists up front (else `NOT_FOUND`, *before* the new project is created — never leaves a project pointing at a missing source) and stamps `state.style = { derived_from, applied_at }` into the new session. The field is **omitted entirely when not deriving** (lean baseline), rides through every transition because all state writes spread `...state`, and **no gate reads it** (advisory). The orchestrator, seeing `state.style`, does a cross-project `vob_read_state_summary { project_id: derived_from }` (its `intent.answers` carries the source's stored answers) + reads the source `brief.md`/`compose/` to (a) pre-propose the *stylistic* intent keys — `tone`, `target_platform`, `target_duration`, `music_vo`, and (when applicable) `captions_style`/`audio_treatment` — but **never `key_moments`** (content-specific to the new source); (b) seed a "Styled after: <id>" line in the brief; (c) hand the composer a "mirror the LOOK, not the cuts" reference to the source composition (`compose/index.html` + CSS). `vob_package_output` surfaces `derived_from` in the manifest + README lineage. **No new tool, no allow-list changes**; `--like` only takes effect when creating a NEW project (a resume keeps the original lineage). Cross-project *reads* are deliberately not blocked by the write-guards. (`buildInitialSessionState`/`initProject` in `mcp/lib/session-state.js`.)
